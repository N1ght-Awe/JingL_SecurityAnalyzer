## 1. 漏洞概述

用户输入改变 SQL 语义且未被适用的绑定或固定映射约束才成立；不按拼接 API 名称下结论。

## 2. 危险点清单

Statement、JdbcTemplate、MyBatis ${}、动态表/列/排序、Wrapper last/apply/inSql/exists/orderBy/groupBy/customSqlSegment。

## 3. 分析步骤

区分数据值与 SQL 结构；追踪 DTO 到真实 Mapper/提供器和执行器，读取最终 SQL 与参数映射。检查二次读取、动态分支、空条件和每个可控片段。

## 4. 证据闭合验证

证明 Source→传播→SQL 结构/绑定→执行，核验当前字段的防护、接口权限、数据库方言和可支持影响。服务间输入不是自动可信。

## 5. 防护措施清单

值参数绑定与标识符固定枚举映射分别检查。参数化另一个字段、LambdaWrapper 名称、未知 OgnlUtil 或黑名单不能保护当前片段。

## 6. 常见误报模式

同一可控字段被完整绑定或固定安全映射；固定片段且所有来源不可改变。必须定位实现，不用“满足两项即可排除”。

## 7. 判定标准

源码闭合按共享契约给源码确认；来源或实现缺失保留缺口。SQL 文本构造证据不能单独宣称数据库执行或数据泄露。

## 8. 置信度评估

按来源、最终查询、防护和影响证据说明强弱；无固定百分比。

## 9. 核心纪律

只验证目标语义所需的测试数据和查询，不引入破坏性操作；运行验证使用真实查询逻辑及兼容数据库。
