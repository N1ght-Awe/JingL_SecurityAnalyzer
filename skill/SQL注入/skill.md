## 1. 漏洞概述

不可信值或标识符改变实际 SQL 语义且未受适用绑定/映射约束才成立。MyBatis #{} 值绑定与 ${} 文本替换需区分；标识符不能靠值绑定解决。不能按 API 名称或无白名单单独确认。

## 2. 危险点清单

- MyBatis XML/注解/Provider 的 ${}：WHERE 值、ORDER BY、表/列/别名、动态标签与二次读取。
- MyBatis-Plus last/apply/inSql/exists/notExists/orderBy/groupBy/customSqlSegment；读取实际 SQL 和绑定方式。
- Statement/JdbcTemplate 与自定义查询构造器拼接，存储字段再次进入查询。
- 动态 DELETE/UPDATE 的空条件分支；可能是业务批量操作缺陷而非 SQL 注入，按真实根因归类。

## 3. 分析步骤

1. 按文件类型和 SQL 上下文分片搜索；根据 Mapper 注册/namespace/构建确定映射文件，不只搜小写 mapper 文件名或目录。并行搜索注解、Provider、Java 构造器和执行器，配置占位符单独分类而非全局排除。
2. 区分值、标识符、完整片段与最终绑定，追踪 DTO→Mapper/Wrapper→实际执行器及数据库方言。
3. 追踪外部输入、导入/数据库二次读取、任务/配置来源；内部计算仍可能受攻击者影响，不按标签判不可控。
4. 读取 OgnlUtil/SqlInjectionValidator 等集中工具实现，区分裸片段与包装片段；两组都保留，不能以包名前缀跳过。逐使用点检查返回值、失败处理与分支特例。
5. 核验标识符固定业务映射或语法约束在确切位置是否充分；字符允许集不自动等于业务授权，所有正则也不自动可绕过。
6. 对空/null/默认条件检查实际可触发的全表操作和权限影响；检查批量、异步、定时及二次注入链。
7. 控制侧关注绑定覆盖、字段映射、插件注册/忽略分支和实际 profile。控制侧通用步骤见 shared-references/protection-audit-methodology.md；已审实现按 shared-references/control-knowledge.md 复用，逐路径核验调用、适用性与后续影响。

## 4. 证据闭合验证

Source/Propagation 证明攻击者如何影响值或结构；Sink 为真实查询执行/构造位置，分别记录绑定、Sanitizer、Guard、方言/条件与 Impact。SQL 文本捕获只能支持构造层结论，不宣称数据库执行或数据泄露。

## 5. 防护措施清单

值完整参数化；标识符固定枚举/Map/Switch 映射到适用业务值。Lambda 方法引用只约束该列，其他动态片段仍检查。字符过滤、黑名单、长度和工具函数名都需按位置/方言核验，不能自动确认安全或绕过。

## 6. 常见误报模式

当前可控字段被完整绑定或固定安全映射，或所有来源证明只能生成安全固定片段。查询使用 ORM、另一个字段参数化或“来自内部计算”不足以排除；集中防护复用仍须当前路径证据。

## 7. 判定标准

最终 status 与执行状态遵循 shared-references/proof-schema.md；下述为源码判据。源码确认需证明攻击者影响实际 SQL 语义、相关绑定/约束未阻断、触发条件与相称影响闭合，涵盖 JDBC、注解、Provider、XML 和 Wrapper。同路径有效绑定/映射可作反证；未知来源/实现/环境按实际缺口保留。

## 8. 置信度评估

按来源、最终查询语义、防护、条件和影响证据描述置信度；只有 ${} 命中或调用链不够，不用固定百分比。

## 9. 核心纪律

各搜索分片保留覆盖结果，不把配置噪音统计当通用比例。验证使用真实查询逻辑及兼容数据库和最小测试数据，不引入破坏性操作。复现困难不降低严重度。
