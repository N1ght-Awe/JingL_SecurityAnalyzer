name: 路径穿越漏洞分析
description: CWE-22；审查可控文件路径、文件名和压缩条目越过允许文件系统边界。
---

## 1. 漏洞概述

不可信路径导致实际文件操作越过允许边界才成立。区分读取、写入、删除、创建、解包与路径信息泄露；URL 层路径变化不自动等于本地文件越界。

## 2. 危险点清单

- 基目录拼接、new File(base,name)、绝对路径、上传原始文件名与下载参数。
- ZipEntry 条目落盘、临时文件名拼接、归档链接、重命名/移动和删除。
- 符号链接/真实父目录和检查到使用之间的替换；URL 路由变化需追至实际文件操作或对应安全边界。

## 3. 分析步骤

1. 追踪请求、MQ、上传、存储二次读取、配置和上游调用；未定位入口是未知，不等于不可控。配置亦需核验可修改主体。
2. 定位真实 read/write/delete/create/move/transferTo/解包执行；File/Path 构造及 exists 仅支持相应构造/存在性观察。
3. 追踪完整基目录和输入组合，按目标平台验证相对/绝对路径、分隔符、点目录和前缀；不能假定任意添加 ../ 都可穿越。
4. 核验路径组件边界与实际文件系统语义；normalize 不解析符号链接，读取查真实路径、写入查真实父目录，按威胁模型检查 TOCTOU。
5. 上传保存、下载读取、临时文件与每个 ZIP 条目分别核验，检查后续使用是否仍为校验的对象。
6. 明确允许访问目录、系统权限和实际影响；控制侧关注边界函数、存储封装、重命名、各操作覆盖。控制侧通用步骤见 shared-references/protection-audit-methodology.md；已审实现按 shared-references/control-knowledge.md 复用，逐路径核验调用、适用性与后续影响。

## 4. 证据闭合验证

Source 为可控路径/条目，Propagation 含解码/拼接，Sink 为实际文件操作，Sanitizer 为路径/文件名约束，Guard 为访问权限，Preconditions 含平台/链接/目录条件，Impact 为实际跨越边界的结果。ZipSlip 要证明解包写入，不以 new File 构造替代。

## 5. 防护措施清单

按路径组件核验真实边界并处理适用的链接/竞争条件；normalize+Path.startsWith 提供词法检查但不独立解决链接。canonical 字符串比较须有目录分隔边界且使用时条件不变。严格单文件名允许集需拒绝 . 和 .. 等点目录；UUID 仅在原名及输入不再影响父目录/后缀路径时阻断路径控制。

## 6. 常见误报模式

实际操作始终受固定映射和真实允许目录约束；相关威胁主体不能影响完整路径。不能只靠配置来源标签、正则允许点号、normalize、检查存在性或某个防护函数名称排除。exists 不能证明读取但仍评估存在性泄露。

## 7. 判定标准

最终 status 与执行状态遵循 shared-references/proof-schema.md；下述为源码判据。源码确认需同时证明可控路径、实际操作、允许边界被越过、适用防护未阻断及前提/相称影响。误报须同路径有效边界或不可控性的证据；来源未定位保留缺口。局部字符串逃逸不证明文件读取。

## 8. 置信度评估

按已证明的操作、边界和未知平台/权限条件描述；不凭 API 名称给高危或固定置信度。

## 9. 核心纪律

使用隔离目录和测试标记验证实际文件操作；不读取真实秘密。兼顾目标平台分隔符、链接/竞争及归档写入；无证据不补造来源或影响。
