# JingL Security Analyzer 2.3.2

面向 Java / Spring Boot / Jalor 的 18 类漏洞分析规则集。提供给现有模型平台后，以“`jingl 扫描 <代码仓或汇总根目录>`”触发，无需部署独立扫描平台。

## 工作方式

发现疑似漏洞时先保存候选实例与原始证据，再去重、筛选和分级，再对筛选出的 P0、P1、P2 开展深度验证；验证深度由漏洞影响决定，不对所有疑似点全面展开。主入口精简，类型规则、验证和报告契约按需加载。

- P0–P3 同时表达严重度与处理紧迫度；保留初评、终评依据及待定标记。
- 源码结论与执行状态分开：待审查、缺失关键源码、待验证、源码确认、确认、误报。
- 局部模拟必须使用真实目标实现；权限等目标需保留实际安全链。POC 生成、构建成功或 mock 输出不算漏洞复现。
- 保留跨仓调用、身份、传输和制品关联；不根据框架注解、内网地址或库名称自动判安全。
- 验证失败、环境缺失、尚未完成的审查都保留在报告里，不变成误报或消失的候选。
- 已核验防护函数在同轮即可复用实现分析；每条路径仍核验实际调用、结果使用、上下文和后续影响。跨轮先核对实现/依赖/配置指纹，变化或未知时重审相关部分。
- 前端与模板先枚举再对账；允许部分报告，不允许将未覆盖范围写成无漏洞。控制侧观察单独呈现，不混入漏洞计数。
- 默认最小充分真实验证；需要启动整套系统或外部服务时先提交具体方案供用户选择，已有明确授权不重复询问。难复现不降低严重度。

## 2.3.2 证据绑定与统计对齐

执行回执将本轮ID、明确列出的调用实例、验证目标与范围、已审源码摘要、仓库声明信息及原始日志绑定；运行前后实读已审源文件，源码变化不得沿用PASSED。已应用防护的全部指纹须匹配本轮有效读取快照，缺失或冲突保留未解决。候选数统一按账本调用实例计算，同根因仅分组。详见 [执行采集](shared-references/poc-execution.md) 与 [防护复用](shared-references/control-knowledge.md)。

绑定用于拦截证据串用，不证明命令实际调用了业务目标、断言覆盖充分或能抵御故意伪造。仓库revision/path是报告声明，执行脚本实测的是已审文件字节摘要；历史报告按原规则校验，不自动升级证据。本次未新增真实业务扫描验收集。

## 2.3.1 判定维护

可控性按服务端实际采信值与约束判断；回传数据、上游权限、单层补偿防护和客户端默认配置不自动决定误报或低级别。路由、CSV/XLSX与URL协议场景按对应规则检查。新报告拒绝未被消费的severity/review_note字段，要求意见进入正式证据、级别依据与复核记录；历史报告继续可读。

## 链路搜索与执行监督

优先直接使用执行平台已有的符号定义、调用层次（谁调用它、它调用谁）和具体实现查询；AST结构匹配与文本搜索补查配置、模板和动态注册。平台未开放这些语义能力时明确降级，不把结构命中冒充调用图。可运行的适配器使用已安装 ast-grep 和 rg，不自动安装；ast-grep 不可用时明确降级。每个终结论须关联原始搜索结果和真实源码读取回执，复核遗漏防护后方可输出；默认最多两轮定向补查，无进展停止。见 [执行监督](shared-references/execution-supervision.md)。

这是证据约束和复核流程，不是自动发现所有调用的引擎；不会保证模型绝不漏读。正式目标保持Java/Spring/Jalor，不因其他语言测试扩展规则范围。调用层次取决于平台已有语义工具，本包不内置通用语言服务器。AST参数依据 [ast-grep CLI文档](https://ast-grep.github.io/reference/cli/run)。

候选发现即写入只追加的本轮账本，交付时核对每个ID的去向；同根因不同调用实例各自审结。复核先保存源码侧防护观察，再与主审对照，区分同上下文复核与独立上下文审阅。复用原来的回执、监督和报告，不新增Agent或常驻平台。详见 [候选登记](shared-references/candidate-ranking.md)。

## 统一报告

在原画像步骤内维护一份简短威胁概览：系统用途、主体、保护边界及待核实条件，复用已有资产与候选。默认由JSON生成同一顺序的Markdown主报告：先看结果与边界，再看问题清单和详情，保留原四个视图。执行回执留在原件和附件，不在正文堆叠。无需新增Agent、服务或建模工具。

## 结构

| 位置 | 用途 |
|---|---|
| `skill.md` | 触发、筛选分级和按影响深度验证 |
| `shared-references/` | 24 份范围、证明、验证、防护复用和报告引用，按需读取 |
| `skill/` | 18 类专项规则，不含教学代码和固定 payload |
| `scripts/validate-architecture.ps1` | 路由、版本、文件和子 Skill 结构检查 |
| `scripts/validate-report.py` | JSON 状态、原始证据摘要、声明覆盖与防护复用契约检查 |
| `scripts/audit_evidence.py` | ast-grep + rg 搜索、源码读取回执及监督证据检查 |
| `scripts/execution_evidence.py` | 运行明确指定的验证命令，保存本轮/实例/已审源码绑定与原始执行日志 |
| `scripts/candidate_ledger.py` | 原始候选登记、源码侧初始复核存档与逐实例去向对账 |
| `scripts/render-report.py` | 校验JSON后生成固定结构的Markdown主报告 |
| `tests/` | 维护时使用的契约回归，不随扫描加载 |
| `CHANGELOG.md` | 版本变化、迁移与真实环境对照方法 |

保留既有小写 `skill.md` 路径，供已接入的模型平台继续使用。本仓是平台读取的规则包；需要平台原生 Skill 安装结构时，由接入层适配文件命名与元数据。

## 校验

需要 PowerShell，以及 Python 3.11+（仅标准库）。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate-architecture.ps1
python -m unittest discover -s tests -v
python scripts/validate-report.py <report.json> --evidence-root <报告根目录>
python scripts/render-report.py <report.json> --evidence-root <报告根目录> --out <report.md>
```

报告保留四个视图：漏洞扫描报告、传输链路探测分析、扫描统计、跨代码仓调用链分析。完整候选留在 JSON；旧报告迁移要求见 [报告契约](shared-references/report-schema.md)。

新报告使用 schema 2.3.0、skill/rules 2.3.2，要求原始候选对账、逐实例监督、源码侧初始复核及本次两个绑定，保留轻量threat_model。历史2.3.1及更早报告继续按原契约校验，不能只改版本号伪装获得新证据检查；旧规则携带execution_receipt会拒绝静默降级。防护知识是有证据的 JSON 审查记录，由执行模型读取、比对和复用，不是自动训练模型或无需人工证据的缓存引擎。

当前验证覆盖规则结构与报告契约，未附完整业务目标仓，不宣称已证明真实扫描准确率、召回率、半小时完成或 token 节省比例。
