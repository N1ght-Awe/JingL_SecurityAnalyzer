# 验证证据组织

本文件提供证据呈现方法，不定义新的 status 或 POC 验证模式。最终结论以 proof-schema.md 为唯一权威，字段用 report-schema.md；目标/运行方式分别用 poc-generation.md 和 poc-execution.md。不要求所有漏洞生成独立 Java 单测。

## 从待证属性到证据

对每项记录“证明义务→真实目标与测试条件→观察/原始证据→可支持结论→尚未证明部分”。可用下列五项作为八维证据的阅读视图，不能替换原字段：

| 阅读视图 | 对应八维 | 必须区分 |
|---|---|---|
| 攻击输入可控 | Source、Preconditions | 测试能构造 DTO 不等于真实攻击者能提交该字段 |
| 真实传播可达 | Propagation、Sink、Transport | mock sink 命中只证明测试范围的调用，未证明真实文件/数据库/网络结果 |
| 防护覆盖与有效性 | Sanitizer、Guard | 未读、观察到不存在、存在但不适用是不同事实；已审实现按 control-knowledge 复用 |
| 反证与触发条件 | Guard、Sanitizer、Preconditions | 兄弟方法不对称或单层认证薄弱只是线索，不能替代业务政策和完整授权链 |
| 相称危险效果 | Impact | 实际目标突破待证边界才支持运行确认；不按断言数量、返回码或耗时阈值确认 |

## 测试设计与运行检查

使用真实目标方法/依赖/安全逻辑；mock 仅替换与待证属性无关的外部组件，列替换边界。下载 mock 返回空流不能证明读取了未授权文件；过滤器被省略的 Service 测试不能证明 HTTP 接口越权。

正负对照保持同一相关安全路径，只改变待证条件。权限验证使用政策明确的主体/资源及真实授权链；合法公开读取不能仅因写接口有校验就判越权。失败对照支持反证时才能判误报，一次 POC 未触发保持具体缺口。

多步利用在同一明确场景中顺序执行或显式准备夹具，不依赖不同测试方法隐含执行顺序及字段状态。优先使用测试框架断言；若使用 Java assert，显式启用并验证断言实际执行。编译通过、零测试或退出码0都不单独代表漏洞目标通过。

资源消耗在有总量/时间边界的受控进程中验证增长或限额失效，记录同环境对照、实际操作次数与结果。超时是观测，不自动等于 DoS；不能把 ZIP 保护配置当成正则防护证据。测试后的进程/服务资源按计划释放。

## 输出与后续验证

围绕现有 trigger、exploitation、reason、validation、remediation 输出，可附攻击输入表、对照和证据映射表；不强制所有发现复制长篇七章节报告。CVSS 如使用需列向量及证据，不取代 P0–P3，也不从案例复制固定分数。

HTTP 入口依据 http-extraction.md；复杂绑定再读 http-poc-extraction.md。请求推导标明“未重放”，实际 scope 不升级；单元测试通过只支持已测目标。完整系统为证明所必需时给出具体方案让用户选择；已有授权则继续。未启动保留源码结论、阻塞原因、计划和级别，不声称已复现。
