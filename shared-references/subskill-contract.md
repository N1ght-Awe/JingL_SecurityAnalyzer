# 子 Skill 契约

深审选中的候选时读取对应类型规则，按 proof-schema.md 输出八维证据、防护实现、确切路径、反证、缺口和影响。P0/P1 必须深审；P2/P3 被选中时适用同样标准。

子 Skill 保留九部分：概述、危险点、步骤、证明义务、防护、排除条件、判定、置信度、纪律。只存模型需要遵循的业务/技术约束；不放教学案例、示例漏洞代码、固定 payload 或未经校准的百分比。

“确认”判据为源码层面审查条件；最终 `status`、验证状态和证明范围由主审按 proof-schema 决定。必要实现未读为未知；没有运行环境不等于缺失源码。无专用 proof-pattern 时写明通用八维证明义务，不编造模式编号。

验证目标和最小真实执行范围按 poc-generation.md；不把所有类型一律提升为 HTTP 全栈测试。规则变更后检查相关正反及未知情形，维护材料放测试目录，不随扫描加载。
