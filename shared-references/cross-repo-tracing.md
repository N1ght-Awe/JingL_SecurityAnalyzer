# 跨仓关联

项目画像总是检查边界；多仓、服务端点、消息、共享存储或链路走出当前仓时执行关联。单仓也可能缺少下游；多目录不代表存在攻击链。

按 repo-boundary-manifest.md 匹配调用者、真实目标、接口/Topic、字段映射、凭据上下文和配置证据。不能仅凭同名字段、同服务名称、共享凭据引用或两个相邻 finding 建立链。

重点闭合输入流、身份流、制品流与传输边界。供应链需串联上传/发布权、存储、分发、下载、执行前可信校验、实际安装/加载。相同凭据引用不证明相同实际值，更不自动证明横向全权限。

每条边记录 caller、callee（未定位为 unknown）、protocol、endpoint_or_topic、data_mapping、auth_context、evidence_refs、missing。图中没有直接 finding 的正常传输节点也保留，避免割断链路。

组合链须逐边证明数据可达、攻击者可控性及前置条件相容；相互矛盾的部署/profile 或身份不可组合。各节点独立成立的发现保留独立编号，链用 related_findings 关联，不重复累计根因数量。

局部目标验证不等于全链执行。缺仓只限制相应链结论，不抹除当前仓已经闭合的问题；跨仓严重度依据可支持的最终影响，不能自动上调至 P0。
