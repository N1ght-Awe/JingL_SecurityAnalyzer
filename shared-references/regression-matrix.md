# 规则回归与真实环境验收

维护时读取，扫描时不加载。architecture 与 Python unittest 验证结构和数据契约，不验证漏洞本身。下列语义情形须结合规则人工检查；真实项目回归另留执行记录，不能因表格存在就声称已测试。

| 情形 | 预期 |
|---|---|
| 筛选出的 P0/P1/P2 | 均进入深度验证，按漏洞影响决定深度；环境缺失保留任务，不增加价值筛选门槛 |
| 18 类索引及子 Skill | 全部可路由，九部分完整，无教学代码块，元数据可读 |
| P0 源码闭合但未执行 | 可为源码确认，仍 P0；不能称运行确认 |
| 手写漏洞副本或 mock 结果 | 不接受为真实目标执行 |
| PASS 缺目标/对照/断言/原始证据 | 报告校验拒绝 |
| 原始日志被修改或不存在 | 摘要校验拒绝 |
| 构建错误、零测试、超时、断言失败 | 分别保留状态与原因，不转误报 |
| 高危尚未完成审查 | 待审查在候选与统计中可追溯 |
| 防护实现缺失 / 部署未知 / 代码未读 | 分别缺失关键源码 / 待验证 / 待审查 |
| 路径字符串同前缀、符号链接 | 不仅凭 normalize/字符串 startsWith 排除 |
| DNS 校验后连接重新解析 | 不能宣称已防重绑定 |
| Java 参数数组或非 shell exec | 继续审程序语义，不直接确认/排除 |
| 过滤器/解析库/受限上下文名称 | 读取实际配置和能力 |
| 无对象注解但服务/数据库策略生效 | 以真实授权链判断；局部 DAO 测试不能代替接口授权 |
| 列表、空集合、默认值、批量对象 | 按业务政策检查范围，不把空结果当安全 |
| CORS 通配 origin + include | 不直接确认浏览器能读取敏感响应 |
| 敏感响应随后仅存内存 | 仍检查接收链路是否已泄露 |
| 上传/下载分别正常但共同抵达执行 | 闭合跨仓制品信任；缺签名单点不自动 RCE |
| 搜索截断、未覆盖语言、低级别未审 | 留统计与局限，不称全量无风险 |
| 兄弟前端仓实际存在但 findings 为空 | XSS覆盖仍必须登记前端，不能按零发现宣称完成 |
| package.json 属于 Node 服务或工具 | 读入口分类，不直接标前端；零特征与搜索错误分开 |
| 必需前端/模板未审或缺框架能力 | partial报告保留局部发现，禁止全局阴性结论 |
| 函数 A 实现已审、新路径确实使用其合适结果 | 可复用实现分析，无需第二轮或重复完整读取 |
| 函数 A 同名不同实现/相关配置变动/指纹未知 | 不能应用旧结论，核查失效部分 |
| A 返回值未用、失败后继续、下游解码/拼接改变保证 | 当前路径不适用；原实现合同未必失效 |
| SQL 白名单有效但对象授权未审 | 不跨风险类型推断安全 |
| 公开读/受限写、第一层失效但第二层阻断 | 不凭不对称或单层缺陷确认，按政策/完整链判断 |
| 防护存在性已核查但不存在 | observed记录缺失事实及证据；未知不伪装成不存在 |
| 用户暂不启动完整系统 | 保留源码结论、BLOCKED计划与级别，不声称复现 |

真实环境为每个适用类型准备漏洞路径、防护生效路径、关键条件未知路径。核对目标行为和证据边界，再比较耗时、token、误报、漏检与未解决项。基准只放测试材料，不增加扫描常驻上下文。

## 2.3.1 维护场景

以下为后续源码行为评估的对照要求，不是已经跑过的真实业务测试；避免把项目复核结论直接固化成全局标签。

| 场景 | 应有判断 |
|---|---|
| 页面从API取得编号再回传，后端直接使用 | 检查当前请求修改能力；上游命名校验不自动覆盖此路径 |
| 后端按已授权ID重查并覆盖回传编号 | 核实覆盖后再追真实数据库写入主体与限制，不制造直接请求注入 |
| 有检入权限者写入，另一用户导出/打开 | 检查跨用户攻击与校验实际范围，不因需要权限或人工审核自动排除 |
| grep无路由命中但有通配转发或404前副作用 | 不因零命中/状态码排除，核查实际处理和目标影响 |
| 单层失效，另一层只校验Referer/URL格式 | 检查是否阻断同一威胁，不能当作通用认证/对象授权 |
| 同名配置出现在两个服务，绑定或路由不同 | 可复用实现证据，结论逐实例保留，不批量套用 |
| CSV打开会解释公式，但DDE启动被禁 | 限制DDE影响结论；其他影响另证，不统一低级别或误报 |
| XLSX字符串单元格保留等号，或仅设置文本样式 | 核查真实类型/模板/生成结构和消费行为，前缀与显示格式不代替执行语义 |
| URL来自API但构造受用户字段影响 | 沿构造与真实协议到消费端核验，系统生成不是安全证明 |
| 协议检查缺少尾锚点但严格限定有效协议 | 不单凭缺少$判断可绕过；反例需匹配真实解析与消费语义 |
| review_note或severity与正式字段分歧 | 新规则拒绝旁路字段；改入证据、原因、priority/grade_basis及复核记录 |
| 报告标题、原因、证据与链路含HTML/Markdown边界字符 | 安全显示文本且保留内容，不形成可执行标签或攻击者链接 |

字段兼容与安全文本输出有程序回归；语义场景须用对应源码与适用环境另作行为验证，不能以关键字断言测试代替模型审查效果。

## 2.3.2 证据绑定与统计口径

运行tests/test_control_bindings.py及tests/test_execution_bindings.py，并保留现有候选账本回归。下列为合成源码/命令及报告契约检查，不是实际业务扫描验收；本次不新增真实扫描验收集，待收集授权样本后另行评估。

| 场景 | 应有结果 |
|---|---|
| 本轮、明确实例、goal/scope及已审源码全部匹配 | 可通过绑定检查，最终确认仍须真实目标/断言/对照证据 |
| 旧运行、兄弟实例、其他goal/scope或仓库声明不匹配 | 拒绝串用，即使原始附件存在且摘要正确 |
| 执行前源码已变，或执行中改变/删除已审源文件 | 前者停止执行，后者记录变化且不得PASSED |
| 共享防护只在其他实例监督下读取，本实例明确关联适用 | 防护全部指纹也纳入本实例执行sources，防护文件变动不得复用旧执行证据 |
| 监督新增/替换read源码，旧回执未覆盖 | 重新取得匹配执行证据，不通过删读记录迁就旧日志 |
| 一条suite声明多个实例 | 仅明确列出的实例可引用，逐项目标/源码绑定；具体断言覆盖另作语义检查 |
| 原始日志、命令、环境、时间、退出或超时状态与报告不一致 | 拒绝；失败无回执仍可如实部分交付，提供回执必须有效 |
| 超时清理进程树受限或失败 | 保留TIMEOUT和cleanup_error，不声称清理干净；操作人员确认残留进程后再重跑 |
| 防护指纹错误、缺少本轮快照、同路径跨仓或混合版本 | applicable拒绝，提示stale/unresolved，禁止自动改写结论 |
| 相关防护指纹相同，仅revision标签不同或合法跨仓调用 | 不因标签或调用方仓不同拒绝；实现仓/文件身份仍须准确 |
| 未应用历史reviewed/stale知识，或未解决防护应用 | 不强制读取业务仓，不阻止明确缺口的部分交付 |
| 同实例重复命中、同根因不同入口/调用点 | 前者沿用ID，后者保留独立实例；候选数与账本/findings一致，根因仅分组 |
| 历史2.3.1等报告与旧规则携带execution_receipt | 原历史报告维持旧契约；旧规则带新字段拒绝静默降级 |

仓库revision/path是报告声明，执行前后的源码摘要才是脚本实测。上述检查不证明模型选全了文件、命令执行了真实业务目标，也不能抵御故意重写整套证据；测试通过不得用于声称召回率提高。
