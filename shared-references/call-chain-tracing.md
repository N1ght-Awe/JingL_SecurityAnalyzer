# 调用链追踪

## 优先读取符号定义与调用层次

先探测当前执行平台实际开放的 IDE/LSP/代码索引能力，记录符号定义、引用、具体实现及调用层次是否可用、索引是否就绪、覆盖哪些模块。优先直接查询调用者和被调用者；可用时不再用逐段全文搜索重建同一关系。IDE界面能展示不代表执行模型已能访问，未暴露的接口不能假报已调用。工具不足时明确降级，不强制换平台或自动安装。

| 需要确定的事实 | 优先使用的能力 | 后续核对 |
|---|---|---|
| 当前调用指向哪个函数 | 跳转定义 definition | 文件、限定符号、签名、重载和源码版本 |
| 谁调用它、它调用谁 | 调用层次 incomingCalls / outgoingCalls | 调用点范围、参数、分支与返回值使用 |
| 接口/抽象方法落在哪个实现 | implementation及类型信息 | Spring实际注入、代理、条件配置 |
| 还有哪些引用或注册 | references，再查配置/模板 | 引用不全是调用；反射、注解和XML注册另行补查 |

平台提供LSP时，按能力声明调用 textDocument/definition、textDocument/implementation、textDocument/references；调用层次先 textDocument/prepareCallHierarchy，再用返回的item查询 callHierarchy/incomingCalls 或 outgoingCalls。这些是协议方法名，不是可以直接敲进终端的命令；已有平台等价工具也可使用。保存请求位置、返回的符号/调用点与原始结果。坐标须遵循工具的行列和字符编码约定，避免把0基坐标当成源码1基行号。

按证明目标逐边展开相关调用，不设固定层数；对同一源码版本、符号及查询方向复用已取得结果，并用已访问集合避免递归环重复展开。零结果只说明当前索引没有给出关系，须先检查索引/模块覆盖与动态绑定，不能直接判死代码。调用图指引需要读取的位置；数据是否沿该边传递、防护是否生效，仍须核对实现。

AST结构匹配用于补足声明/赋值/返回结构定位，rg用于配置、模板、反射字符串和动态注册。audit_evidence.py 的 search 仅适配已安装 ast-grep + rg，不提供LSP服务或语义调用图；不能用运行了该脚本冒充完成调用层次查询。语义导航使用当前平台真实可用的工具，参数与读取回执见 execution-supervision.md。AST 查询须覆盖实际语法，如直接调用、receiver 调用、别名和包装器。ast-grep 是结构搜索，不是完整调用图/污点引擎；同名函数不能证明绑定到该实现。语义索引也须核对构建条件及源码版本。

每个候选建立工作清单：入口/可控字段 → 调用点 → 实现与返回值 → 实际操作，同时从操作反查调用者。每新增影响证明的调用/变换就入清单，读取函数体、分支及配置后才能关闭，不能把找到函数当作追踪完成。已闭合边保留理由和回执，未解析边列缺口；无需枚举无关的整个程序调用图。

Java/Spring/Jalor重点补查接口实现、重载/继承、Bean注入与条件配置、代理/AOP、Filter/Interceptor、安全链顺序、注解/XML Mapper绑定及异步回调。XSS同时核查前端/模板、转义与可信HTML转换。搜到白名单调用不证明返回值被使用或失败分支阻断输入。其他语言的偶发测试不改变本规则正式覆盖范围。

## 源码语义闭合

从 Sink 反向追踪可控字段，再从实际入口正向核对；记录仓库、文件、符号、行号、字段变换和条件。接口与实现、重载、继承、代理/AOP、XML Mapper、异步回调和持久化二次读取均按实际绑定确认。

深度由证明义务决定，不设置“追两层即停止”或“必须三层”的规则。找到常量仍要检查是否可由配置、数据库、发布者或上游攻击者改变；未找到调用方不能当作不可控。

遇到边界读取 cross-repo-tracing.md；需要的仓库未提供则记录缺失位置。代码在范围内但尚未读完属于待审查，不是缺失源码。

存在认证/净化包装器时追到实现及生效配置。全局安全事实只有映射到当前字段、分支、主体与路由才可成为反证。所有权也可能在服务层、查询构造或数据库策略中实现，不能要求固定放在 DAO。

网络节点记录协议、目标、实际客户端实例、TLS 主机/证书验证、代理、请求和响应中的敏感数据。密钥已在不安全响应中泄露时无需重复证明每个 SDK 下游调用；下游影响仍需凭据权限证据。回环、内网、短期令牌和安全存储都不自动排除链路风险。

每次追踪输出已闭合部分、未闭合边、缺口类型及下一步可定位的位置。同一实现的事实可以引用，但最终结论必须适用于当前入口的真实条件。

协议依据：[LSP语言功能与调用层次规范](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_prepareCallHierarchy)。实际能力以执行平台及语言服务声明为准。
